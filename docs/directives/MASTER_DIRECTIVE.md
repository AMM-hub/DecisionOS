**27\. IMPLEMENTATION EXECUTION RULES**

Work in controlled phases.

For every task:

1.  Read the current checkpoint.
    
2.  Inspect relevant implementation.
    
3.  Identify dependencies.
    
4.  Define the task.
    
5.  Define acceptance criteria.
    
6.  Implement.
    
7.  Run relevant tests.
    
8.  Inspect failures.
    
9.  Fix failures.
    
10.  Verify integration.
    
11.  Update documentation.
    
12.  Update checkpoint.
    
13.  Identify the next task.
    

**Task boundaries**

Avoid changing unrelated functionality.

Avoid large uncontrolled rewrites.

Avoid unnecessary refactoring.

Prefer complete, independently testable capabilities.

**When a task fails**

*   Identify the actual failure.
    
*   Determine whether the issue is in the implementation, environment, dependency, test, or configuration.
    
*   Fix the root cause when possible.
    
*   Do not hide failures.
    
*   Do not mark the task complete.
    
*   Update the checkpoint.
    
*   Continue with independent tasks when appropriate.
    

**When a task is blocked**

Document:

*   Blocker.
    
*   Required input.
    
*   Required credential.
    
*   Required decision.
    
*   Affected functionality.
    
*   Possible next step.
    

Do not invent credentials or external results.
